# Mooring 0.3.0 preview 45 — Linux desktops, and pairing with a PIN

Preview 44 was never published, so this preview is the first to include its PIN pairing: **Show Pairing PIN…** on one Mac, **Pair a Mac…** and six characters on the other, with no long code and no need to share the screen first. The preview 44 notes describe it in full. Both Macs need this preview to pair with a PIN; the long code still works for older previews.

**Linux desktops.** Choose **Add Linux Desktop** and enter how you reach the computer with SSH: an `~/.ssh/config` alias or `user@host`. Mooring connects through your own `/usr/bin/ssh`, keys and agent, never asks for an SSH password, and listens on 127.0.0.1 only. Its own viewer then signs in to a VNC server such as wayvnc with RSA-AES inside the tunnel. You type that computer's password for each sign-in; it is sent once and never saved or logged. After two rejected sign-ins within ten minutes Mooring waits before allowing another try. Before you sign in, a read-only check over SSH says whether the desktop is locked. If it is, unlock it in the viewer: Mooring never types a password into a lock screen.

The viewer works like Mac-to-Mac viewing: full screen, with this Mac's menu bar and Dock hidden so the desktop's own top bar is reachable, the same footer below the picture (⌃⌘D) with **Exit Full Screen**, and ⌘ as the desktop's Super key. With Mooring allowed in Accessibility, ⌘-Tab and ⌘-Space reach the desktop too. With **Match this screen** on, a Hyprland desktop shows on a virtual screen sized to the picture area, including the row beside the camera housing, so it fills the screen with no bars. While it is up, Hyprland's own pointer is hidden and this Mac's pointer is the only one. The computer's own screen, pointer and workspaces come back when you disconnect, and on their own within about 20 seconds if Mooring quits or the connection drops. Tested with wayvnc 0.10.2 on Hyprland 0.57 (Omarchy).

**Apple Screen Sharing is gone.** Mooring no longer opens Screen Sharing for any Mac. A Mac address saved for it by an earlier preview is listed as **Needs pairing**, with **Pair a Mac…** or **Remove…**.

Known limits: on a large virtual screen the picture updates only a few times a second while much of it changes. The pointer over a Linux desktop is always this Mac's arrow, not the desktop's I-beam or resize shapes. Only one viewer at a time gets the virtual screen; another one connecting meanwhile sees the computer's own screen.

Local validation covers Rust, including the VNC client against a fake server, the SSH tunnel and desktop check with fake ssh, the virtual screen script under sh and dash, and PIN pairing; the native input, media and session suites; the Linux viewer's layout and input; encrypted loopback streaming; the packaged CLI; and the app build. Signing in to wayvnc through a real tunnel and the virtual screen were checked against a real Linux laptop. PIN pairing between real Macs, and viewing a Linux desktop from a second Mac, remain separate acceptance checks.

Use **Check for Updates…** on each Mac, or download the ZIP. Updates install while idle. Apple silicon and macOS 14 or later; Developer ID signed, notarized and stapled. All tests, builds, signing and packaging run on the local Mac. GitHub Actions remains disabled.
