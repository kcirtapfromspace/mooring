# Testing the preview on another Mac

Download `Mooring-v0.3.0-preview.37-macos-arm64.zip` and `SHA256SUMS.txt` from the [public release](https://github.com/kcirtapfromspace/mooring/releases/tag/v0.3.0-preview.37). Mooring supports Apple silicon only and requires macOS 14 or later. Apple's High Performance mode additionally requires compatible Macs at both ends. The experimental native session requires this preview on both Macs. The download contains `Mooring.app`. Automatic updates preserve the existing installation location.

1. In the download directory, verify the ZIP with `shasum -a 256 -c SHA256SUMS.txt`.
2. Quit older Mooring copies. Extract the ZIP and replace the previous app in Applications with `Mooring.app`. Saved Macs and existing configured preferences are preserved.

## Apple Screen Sharing

1. Open Mooring, choose **Add Mac**, enter the remote hostname or IP, and click **Add & Connect**. The address is the only required field. Name and port are under **More Options**; port defaults to 5900. On the remote Mac, Screen Sharing must be enabled for your account. Saved Macs now appear under the menu's **Apple Screen Sharing** submenu.
2. Choose **Enable & Connect** when asked, then grant the installed Mooring app Accessibility access in macOS. Verify that connection continues automatically after the grant. Alternatively, **Connect Without Automation** should open a manual session. Sign in through Apple Screen Sharing if prompted.
3. On a fresh installation, verify Auto mode and full screen work without opening Settings or marking a home network. Leave the identified session on a healthy direct Wi-Fi/Ethernet path long enough for the 35-second learning span and subsequent mode-policy observations. Confirm Apple's actual mode on both Macs if Mooring requests a High Performance trial; the exported document alone is not proof.
4. Close the managed window and verify that Mooring pauses. Resume when ready. Test sleep/wake and network changes; unrelated Screen Sharing windows must remain untouched. A familiar path still requires healthy checks before automatic opening.
5. For optional overrides, open **Settings** and try Standard or Prefer High Performance. Expand **Advanced** to inspect detailed automation and home controls. Previously configured users should retain their existing choices rather than being reset to new defaults.

## Experimental native session

1. On the Mac to share, choose **Share This Mac…** and click **Start Sharing**. Grant Screen Recording when macOS asks, then click Start Sharing again if needed. If macOS asks whether Mooring may accept incoming connections, allow it. Click **Copy Pairing Code**. Close the Share window and confirm the menu still shows **Stop Sharing This Mac**: sharing continues without the window.
2. Move the code to the viewing Mac without posting it anywhere shared; until it's used, it works like a password. It pairs one Mac, once, within 10 minutes, while sharing stays on. On the viewing Mac, choose **Connect with Mooring…**, paste the code and click **Pair & Connect**. Leave **Address** empty on the same local network; enter the sharing Mac's IP address for other paths. The sharing Mac's **Settings** should now list the viewing Mac under **Macs that can connect to this Mac**. Pasting the same code again, on either Mac, must be refused with a message to copy a new code.
3. Away from home (another network, with a VPN such as Tailscale running on both Macs), connect from the menu. Mooring tries every address in the code and connects through the one that works; its log says "by address N of M". Back home, it should connect through the local address again, after at most one slower attempt. Settings → Paired Macs shows the main address and how many others there are.
4. Verify the remote display appears and enters full screen, and that the status bar shows frame rate, round-trip time and the sharing Mac's resolution ("no new frames displayed" can mean a still screen or a viewer that is not drawing). Toggle **View → Diagnostic Footer** with ⌃⌘D: hiding it must give the picture its full height, and the choice must survive reconnecting and restarting Mooring. **Settings → Viewing** must reflect the same preference. Toggle **Stats for Nerds** with ⌃⌘I while the footer is hidden, including during full-screen control. Both shortcuts must act locally; ordinary ⌘D and ⌘I must still reach the remote Mac. Verify live codec, resolution, frame rates, received bitrate, host target, timing and recovery values while moving a window, then stop: zero frame rates are valid, latency becomes unavailable if no frame is shown, and RTT stays separate. Host values must become unavailable when its samples are more than three seconds old; ending the session must clear live stats. Scroll the overlay in a small viewer, and use its Save Diagnostics action. The session is view-only until the sharing Mac clicks **Enable Keyboard & Mouse…** and allows Mooring in Accessibility. Confirm there is exactly one pointer in both view-only and control modes.
5. With control enabled, test typing, repeated shortcuts such as Cmd-Z twice, modifier keys, clicks, double-clicks, drags, right-clicks and trackpad scrolling. Switch away from the viewer mid-drag or mid-keypress and confirm nothing stays pressed on the sharing Mac.
6. On the viewing Mac, click **Allow ⌘-Tab…** in the viewer's status bar and allow Mooring in Accessibility; the button disappears within a second. With the viewer focused, ⌘-Tab, ⌘-Shift-Tab and ⌘-Space must act on the sharing Mac only. ⌘⌥Esc must open this Mac's Force Quit window and ⌃⌘F must leave full screen, after which ⌘-Tab switches apps locally again. Menu bar: while controlling in full screen, move the pointer to the top edge and click the sharing Mac's Apple menu and an app menu. They must open on the sharing Mac, and neither this Mac's menu bar nor the viewer's title bar may slide down; at the bottom edge this Mac's Dock must stay hidden. **Exit Full Screen** in the viewer's status bar and ⌃⌘F must each leave full screen, and swiping between Spaces on the trackpad must show this Mac's desktop. In a view-only session, the top edge must show this Mac's menu bar as usual.
7. Pointer: while controlling, move over text, a window edge and a link on the sharing Mac. The pointer should become an I-beam, resize arrows and a pointing hand, each at full size. Clicks must land exactly at the arrow's tip, the I-beam's center and the hand's fingertip, in every corner of the screen as well as the middle. Screen size: with **Match Shared Screen to This Mac** on (the default), full screen on the viewing Mac should, after a second or two, show the sharing Mac's desktop filling the screen with no bars. The status bar should show the viewing Mac's size in pixels, for example 3024×1832. Turn the option off and the sharing Mac's own display should return. End the session and the sharing Mac's original display arrangement must be restored. Check which codec the session uses: on the sharing Mac, the session log should say "streaming HEVC 4:4:4 … 4:4:4 chroma confirmed". On each Mac, check the launch self-test result. Gestures: while controlling, pinch to zoom in Preview or Safari, rotate an image in Preview, and double-tap with two fingers (smart zoom) on a web page; each should act on the sharing Mac as it would locally. Three- and four-finger swipes for Spaces and Mission Control stay on the viewing Mac. Sound: play a video or music on the sharing Mac; it should play on the viewing Mac in stereo, without crackles, and in step with the picture (the design target is about a tenth of a second of delay; report any noticeable lag). Latency: while the picture is changing, the viewer's status bar shows the time from a screen change on the sharing Mac to it appearing here ("NN ms latency"). Note it for typing, scrolling and video, on the home network and elsewhere. Then turn on **Lower Display Latency (May Tear)** on the viewing Mac, repeat, and report the latency and whether scrolling or video shows a tear line. Pacing: on the sharing Mac, `mooring telemetry` shows `bitrate_mbps` falling when the connection slows and `send_queue_kib` and `queue_wait_ms` for its send buffer; its session log notes each reduction ("pacing:"). After typing stops, the viewer must show the final text, never a slightly earlier frame. Versions: with different versions on the two Macs, the viewer's bottom bar says which runs what. From preview 20 on, when the sharing Mac is older, **Update It** asks it to download its update, and **Disconnect and Update** ends the session so it installs; the viewer reconnects on its own within two minutes, provided the sharing Mac shares automatically. Settings: **Settings…** in the menu bar holds sharing, viewing, paired Macs and updates; each change applies at once, including to a running session. Switch the viewing Mac's output (for example to headphones) mid-session; sound should resume within a second or two. Turn off **Play Sound from Shared Mac** and sound should stop at once. The viewing Mac's session log reports sound every 10 seconds ("viewer sound, last 10 s"): packets, missing, ran dry and trimmed should stay near zero on a quiet network. Then test colored terminal text and small UI text for legibility, window dragging, scrolling and video playback. Note any stalls, stale regions or dropped frames.
8. Close the viewer, then reconnect from the paired Mac's name in the menu and from **Open Connections…**, where pairings are listed with Screen Sharing Macs. Leave a session idle past the sharing Mac's display-sleep time; it should stay connected. After **Reset Pairing**, the saved pairing must fail; **Remove** in Connections must forget a pairing.
9. Per-Mac keys, the first time both Macs run preview 20 with a pairing made by an earlier version:
   1. Connect from the viewing Mac's saved pairing, without pairing again. It must connect normally.
   2. On the sharing Mac, **Settings** must list the viewing Mac by name, "Paired … from the old code · connected now". The row below it must say the old pairing code works until a date a week away.
   3. Disconnect and reconnect. The viewing Mac must connect again; its session log says "viewer connected with device".
   4. On the sharing Mac, click **Remove…** next to the viewing Mac. Its session must end at once, and the viewer must say the sharing Mac no longer accepts it and stop reconnecting, not retry.
   5. On the sharing Mac, copy a pairing code and pair the viewing Mac with it. The list must show it again, without "from the old code".
   6. Click **Stop Now…** on the old-code row and confirm. The row disappears; the viewing Mac still reconnects with its own key.
10. On the sharing Mac, click **Stop Sharing** and then **Start Sharing** again within ten seconds. The viewer must show **Reconnecting…** and reconnect in the same window, still in full screen. Repeat with the sharing Mac's Wi-Fi off for about 15 seconds, then on. **Cancel** must stop the attempts. Closing the viewer must not trigger reconnection. Sleeping or locking the viewing Mac ends the session without reconnecting while it sleeps; see the next step for what happens after it wakes.
11. Overnight, with the wake-recovery build on the sharing Mac, **Share this Mac automatically** on, and its display set to turn off after a few minutes:
    1. With a session on, close the viewing Mac's lid. After the sharing Mac's display turns off, its Share window says "its connection wakes this display". Overnight is the real test.
    2. Open the lid and unlock. The viewer reconnects by itself in the same window within a few seconds, without **Reconnect**, RDP or Screen Sharing. The viewing Mac's log says "reconnecting the paused viewer". The sharing Mac's log says "waking it", up to three "remote wake activity" entries, then "awake and unlocked … ms after waking for the approved Mac". Repeat several lid-close cycles, including overnight.
    3. Close the viewer window instead, wait past the display-off time, and connect from the menu bar. It must connect the same way.
    4. Lock the sharing Mac so it asks for its password: ⌃⌘Q on it, or another app that locks it. A connection makes at most three remote activity requests, a second apart. It must never capture the covered screen or inject input. If the session stays covered, sharing stops after 5 seconds and waits for an unlock; further attempts must not wake it again. Unlock it with Screen Sharing. The viewer must reconnect within a few seconds. An eligible session with a display that failed to wake should instead say "Still listening" and permit another approved connection.
    5. If an update installs while the display is off, the sharing Mac listens again after the relaunch without waking its display, and the next connection still wakes it.
12. With **Share this Mac automatically** off: Stop Sharing, lock the sharing Mac, and put it to sleep. Each must end the session with a stated reason after the viewer's reconnect attempts, and unlocking must not resume sharing. Then turn the option on. Quitting and reopening Mooring must start sharing without a prompt. After a lock or display sleep, the sharing Mac keeps listening, and a connection wakes it (step 11). After a system sleep, sharing resumes on wake. **Stop Sharing** must keep sharing off until you start it again.
13. Copy text in any app on the viewing Mac and paste it on the sharing Mac through the viewer, then the reverse. Repeat with styled text from TextEdit, and with a screenshot copied with ⌃⇧⌘4 and pasted into Notes or Preview (terminals paste only text with ⌘V). Each copy should cross once: the session log on either Mac must not show the same item being sent back and forth. Copy a password from a password manager and confirm it does not arrive on the other Mac. Turn off **Shared Clipboard** in the menu bar on one Mac and confirm copies no longer cross in either direction. Note whether macOS asked to allow Mooring's clipboard access, and on which Mac.
14. While connected, run `/Applications/Mooring.app/Contents/Resources/mooring telemetry` in Terminal on either Mac and scroll or drag a window on the sharing Mac. From away, `keyframes` should stay at 0 between screen-size changes, with `skipped_fps` and `queue_wait_ms` near 0, and `bitrate_mbps` should climb back toward 25 over the first minute; before preview 24 it fell to 4. With a busy screen on a slow link, `link_mbps` shows what the link carries, and `bitrate_mbps` should settle just under it without a stall every 10–15 seconds. At home, after a Wi-Fi interruption, note how long `bitrate_mbps` takes to return to 25. Try `mooring tune --bitrate-mbps 15`, `--max-width 2560`, `--fps 30`, `--in-flight 1` and `--keyframe-seconds 2` (the old behavior), and note how frame rate, `send_ms`, `encode_ms` and responsiveness change; `mooring tune --reset` restores the defaults. [TELEMETRY.md](TELEMETRY.md) explains each field.
15. Updates: the menu bar shows **Check for Updates…**. When the next release is published, leave both Macs idle, with no session connected; within about four hours each should relaunch on the new version by itself. Choosing **Check for Updates…** checks immediately. Report whether an update ever interrupted a session.
16. **Save Diagnostics…** in the Share window and **Diagnostics…** in the viewer save measurements only. Attach them, or a few telemetry lines, to your report.

The distribution is Developer ID signed, notarized and stapled. macOS may still show its normal first-launch downloaded-app confirmation. If **Apple could not verify Mooring.app** appears, confirm that you opened the extracted 0.3.0 preview 37 app rather than an older copy; do not change Gatekeeper settings. Local development builds are ad hoc by default.

## What to report

- Both Mac models, macOS versions, display resolutions and scale, and connection type: Ethernet, Wi-Fi, off-site, travel router, Tailscale or WireGuard.
- Apple Screen Sharing: whether address-only Add & Connect, permission auto-continuation, saved-Mac persistence and full screen work; whether the default flow avoids Settings; whether existing preferences survive an update.
- Apple Screen Sharing: whether Auto requests a suitable mode, Apple's actual mode agrees, and fallback reconnects only the expected session. Include the displayed reason, not private network details. Note any unexpected reopen, duplicate window or repeated High Performance trial.
- Native session: telemetry lines from a busy moment, the tuning that felt best, pairing, moving over and reconnect success, time to first image, displayed frame rate and round-trip time, text legibility, typing/scrolling delay compared with Apple Screen Sharing, stuck keys or buttons, and exactly how any session ended.
- For any unexpected disconnect, the session log from both Macs: `/usr/bin/log show --last 2h --style compact --predicate 'subsystem == "dev.mooring"'`. It contains Mooring's reasons and timings only, but review it before sharing.
- The permission prompts each Mac showed, and whether denying one produced a clear message.

Do not include passwords, pairing codes, clipboard contents, private screen recordings or session keys. RFB timing does not measure bandwidth or video latency, the native session's round-trip time is not display latency, and a travel bridge can make separate locations look like one familiar network.

## Local build and release checks

All compilation, tests, linting, signing, archive creation and Gatekeeper validation run on the local development Mac. Apple scans the signed archive through its notarization service. GitHub stores source and release assets only; Actions remains disabled.

```sh
./scripts/ci-local.sh
MOORING_CODESIGN_IDENTITY='Developer ID Application: YOUR NAME (TEAM_ID)' \
  MOORING_NOTARY_PROFILE=Mooring \
  ./scripts/notarize-release.sh 0.3.0-preview.37
```

The local suite includes 232 Rust tests (10 CLI, 41 core, 18 platform, 163 session), 73 Swift session-parser checks, the defaults/home-state regressions, loopback CLI integration, and the native Swift checks: input boundary, gesture events read back through AppKit, Command key-up dispatch and local diagnostic shortcuts (110 checks), Opus sound encode, decode, playout buffer and send bound, privacy classification, hardware H.264 encode/decode with recovery and the two-frame in-flight bound, session boundary with pairing over loopback, the pointer image and diagnostic sample freshness, and an encrypted 1080p loopback stream. The public release includes the app archive, signed update feed and checksums.

Local tests do not verify live two-Mac negotiation, a real native session between two Macs, display behavior or performance. Complete the checks above on the second Apple silicon Mac.

When changing the updater or its feed, also run `./scripts/test-update-local.sh`. Its isolated old installation must follow a legacy feed redirect, verify and install an update, relaunch carrying the canonical feed URL, and refuse a tampered archive and an altered feed. This loopback test is separate from checking public GitHub downloads and updating an installed copy on another Mac.
